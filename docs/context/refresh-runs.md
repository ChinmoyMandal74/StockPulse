## Refresh runs — the history page
**`/refreshes` (admin only, linked from the console's Data section) tracks every refresh run, manual or scheduled (2026-09-15).** `refresh_state` is the live flag and is deleted when a run ends; `refresh_runs` (one row per run) and `refresh_rounds` (one per round) are what is left afterwards. Kinds: `refresh` (plain price Refresh, a run of one round), `all`, `missing` (Fill missing), `nightly`, `nightly-full`, `nasdaq` (the three exchange pulls as one run). As-of views are lookups, not refreshes, and are not recorded.

- **Linking a stateless round to its run**: `refresh_state.run_id`. The browser loop passes `&run=<id>` on every `/api/stocks?refresh=1`, the workflow passes `runId` in its body, the NASDAQ page passes it between its three calls. A round lands on `running.runId`, else the id it was given — so a round whose 4-minute flag aged out still lands on the run that started it.
- **Credits are MEASURED**: `fetchJson` adds each response's `Api-Credits-Request` header to an `AsyncLocalStorage` meter (`creditMeter`) that `metered()` opens around each round's `computeStocks`; `fetchProfile` counts pulls and refusals into the same meter. Outside a metered round the store is undefined and nothing is counted.
- **Outcomes**: `complete` (finishLiveRefresh's covered branch), `incomplete` (the client's or the job's DELETE — gave up), `stopped`, `failed` (a plain Refresh or NASDAQ pull that errored), `abandoned` (still `running` with no update for `RUN_ABANDON_MS`, 6 min — swept lazily by every read, so no job has to), `running`. **`finishRun` only closes a run still running**, so the client's give-up arriving after a Stop cannot overwrite it.
- **Stop** (`POST /api/refresh-runs/stop`): clears the flag, marks the run `stopped`, sends the report. The loop driving it is told on its next round — `/api/stocks?refresh=1&run=<stopped id>` answers `{stopped:true}` and computes nothing (measured 0.4s, no round written), the cron route answers `{done:true, stopped:true}` and the workflow exits 0. **Without the run id the loop would have carried on as plain refreshes**, which is why every caller passes it.
- **Reports are stored on the run** (`report_html`, whether or not mail went out — `sendRefreshReport` now builds for a tracked run even without `MAIL_READY`), with failed and still-missing symbol lists; the page shows the report in a sandboxed iframe.
- **The missed-night alarm is a Vercel cron, not GitHub** (`vercel.json`, `GET /api/cron/watchdog` at 23:30 UTC — 7:30 PM EDT / 6:30 PM EST; Hobby crons fire somewhere in the hour). The failure it exists for is GitHub's scheduler not firing, and a watchdog on the same scheduler would miss the same night. It mails only for `missed`, `failed`, `abandoned`, `incomplete` or `stopped` on today's New York date; `running`, `pending` and `untracked` stay quiet. Vercel sends `Authorization: Bearer $CRON_SECRET`, which `isCron` already checks. `?dry=1` returns the verdict without mailing.
- **`nightVerdicts()`** judges each New York day by the newest nightly-kind run started that day (any trigger — a workflow_dispatch counts): ok / running / missed / pending (today before 5 PM) / untracked (before the first recorded run) / the run's own status.
- **The workflow** now sends `trigger` (`manual` for workflow_dispatch), the Actions `runUrl` (stored as the run's link, GitHub URLs only), and the `runId` from its start call on every round; it exits 0 on `stopped`.
- **Retention**: `pruneRuns()` rides every finishLiveRefresh — 90 days of runs, 30 of rounds. **Tracking never fails a refresh** (`trackSafe`), the bars rule.
- **The page**: the live run (progress against the run's own targets, rounds, ETA at 7 profiles a round, credits so far, last round vs 610, GitHub link, Stop), a health strip (last nightly, 14 New York nights, company-data age buckets + the Fill missing count + prices-through), trends (nightly run time over 30 runs coloured by outcome, credits per day stacked by kind), filterable history (type / trigger / outcome), and a run dialog (round chart with the 610 line, refused rounds in red, the coverage curve, a round table, the stored report). Polls every 10s while a run is live, 60s otherwise.
- Verified: db functions against the real tables with test rows removed afterwards (13 checks — round numbering, aggregates through an error round, Stop not overwritten, abandonment sweep, report storage); a local route walk (anon/guest 302 and 403, admin 200, 404 for an unknown run, the stopped short-circuit, watchdog 401 without the secret); the workflow's jq payloads; headless page runs over synthetic history (live card, Stop, 14 nights, trends, filters, dialog with rounds and report).
