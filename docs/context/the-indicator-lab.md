## The indicator lab
`/lab/<SYMBOL>` builds a short-horizon indicator, draws it under the price, and reports what it does — for that stock live, and for the whole universe from a precomputed grid. Reached from **Indicator lab** beside Signal study on the stock page.

**Three indicators so far.** `skip` appears in both and is 12-1's trick at a short horizon: the recent days are where reversal lives, so leaving them out asks for continuation without buying the bounce.

- **Risk-adjusted velocity** — a short-horizon return divided by the stock's own volatility. Knobs: lookback, skip, vol window, smoothing.
  - **`compute(series, params, id)` takes the whole bundle** `{ closes, score, dates }` rather than closes, because the two indicators read different data with different start dates. Threading two signatures through three surfaces would have been worse than one bundle everywhere.
- **RSI** — Wilder's plain reading. Knobs: period, skip, smoothing. Verified against `BarMath.rsiSeriesAt` at **gap 0.00e+0**, and against the screener's own RSI column (61.1603 both).

- **`indicators.js` is shared three ways** — the page, the server and the offline grid — for the same reason `barmath.js` and `action.js` are. A second implementation of "vol-normalised 10-day return" would have drifted inside a week. Verified against the shared bar maths on creation: `windowReturn` agrees to **0.00e+0** and `realisedVolSeries` to **1.14e-13** once the parameterisations are lined up (that one takes two endpoints, this takes length-and-skip, so its 252→21 is lookback 231 skip 21).
- **Series are oldest-first here**, the reverse of `barmath.js`, because charts and rolling windows both read forward. Flip once at the boundary rather than reasoning about a reversed index in every loop.
- **The rolling volatility requires its full window, which deliberately differs from `barmath.js`.** That function reads one date from whatever history it has; this one draws a line, and a line whose early points used 20 returns and whose later ones used 126 is not one measurement along its length.
- **The forward horizon is selectable — 1 week, 2 weeks, 1 month, 2 months, 3 months — and nothing is hardcoded to 21.** `HORIZONS` lives in `indicators.js` because that is the module all three surfaces load, and a page offering a horizon the grid never computed would snap silently to the wrong row.
  - **No forward-return array is shipped.** The browser has the closes, so `forwardReturn()` derives it for whichever horizon is chosen. Sending one array per horizon would have been five copies of something the page can work out, and it is the only way an arbitrary horizon could work at all.
  - **The overlap discount follows the horizon**, which is the point of showing it: MU's 4,638 usable sessions are **939 independent observations at a week and 73 at three months**. A three-month test looks like it has thousands of points and has seventy-three.
  - The grid covers **every indicator × every horizon** — 1,160 rows, five horizons × 232 settings — and snaps to the nearest computed horizon the same way the parameters snap, saying so when it does.
- **The browser computes the indicator, not the server.** A round trip per slider drag would make the control feel like a query. `/api/lab` ships bars and forward returns; the page recomputes the indicator and every statistic through the same modules the server uses. Redraws are debounced 90ms while the number beside the slider updates immediately.
- **The decile panel is the one that matters for a non-monotonic indicator**, and it is why RSI was worth adding. A correlation measures a *straight line*, so a relationship where both ends pay and the middle does not cancels itself out and reports zero — which is exactly the shape RSI is supposed to have, and why the model's own `rsiScore()` is a curve rather than a slope. Live demonstration on MU: **correlation 0.0440, which reads as nothing, while decile 9 returns +7.49% against a +3.46% overall mean.** Bars are measured against the overall mean rather than zero, because zero only tells you the stock went up. Buckets come from the lab's own bucketing.
- **The scatter colours the dots by era**, blue before 2020 and cyan after, with a fit line for each and the two correlations in the legend. The regime split every result on this project has shown is the thing to look for, and a reader should see two populations rather than consult a card. Clicking a legend chip hides that era; hiding both is refused, since an empty chart is not a view of anything.
- **A full recompute redraws both charts in 28ms** for MU's 4,680 sessions, comfortably inside the 90ms debounce. Dot radius steps down above 1,200 and 2,500 points, `dotNodes` is captured once per render, and the middle-99% axis with strays pinned in amber exists because: a handful of extreme fortnights would otherwise press every other point into a band a few pixels tall.
- **The page is a machine for finding things that are not there, and is built to say so.** Four sliders over one stock is thousands of combinations and some will look excellent by chance. So the **universe-wide result and the pre-2020 / post-2020 split sit on screen beside whatever is being tuned**, and the caption names the best |t| anywhere on the grid so a promising-looking cell can be compared against it.
- **`lab-grid.js` calls `compute()` rather than composing the indicator itself.** The first version inlined the composition so it could cache volatility across parameter sets — a second implementation of the indicator, which is the exact thing `indicators.js` exists to prevent, and untenable the moment there were two. The caching bought seconds in a script that runs offline. One grid per indicator now, over that indicator's own knobs.
- **`lab-grid.json` is committed derived data.** 192 settings across two indicators, 60 KB, rebuilt by `lab-grid.js` in 28.1s against the local copy. Shipping it static means the page costs the server nothing; the page prints the build date so a stale grid is visible rather than silent. Re-run it after a backfill.
- **Log price axis above a 4x range**, the same rule the price chart follows — MU ran from $70 to $1,033 over three years and a linear axis flattened all but the last few months onto the floor.
- **What the grid says so far: nothing, for any of the three.** RSI's best top-decile t is **2.73** across 40 settings (it was 1.76 before the universe was pruned — the pool got easier, the indicator did not get better) — and note that is the *cross-sectional* view, where the per-stock decile shape above largely washes out.
- **What the grid says: nothing, for either of the first two.** Velocity's best top-decile t over the full period is **2.76** across 144 settings and the slope's is **0.87** across 48 — **1.73 and 0.80 respectively before the universe was pruned.** A number that moves that far because 19 laggards left is a number about the sample. With that many tests anything under about 3 is noise, and the split is the familiar one — the slope reads pre-2020 t −1.3, post-2020 t +2.0. **A better-estimated version of a flat thing is still flat**, which is the useful answer: the delta's problem was never its estimator.
- **`num()` returned 0 for null**, because `Number(null)` is 0 and finite. It never showed while the only input was closes, which are never null — the moment the score arrived, with 273 blank sessions before a symbol is scoreable, slopes were being fitted from a fabricated zero up to the first real reading. Caught by a count that was impossible: 4,988 slope values from 4,734 scores. **Reject the empties before coercing, not after**, and check counts against what the input can support.
