## Frontend layout
Everything above the table is **one bar**. There is no separate masthead, no tab rail, no chip row — they were merged to reclaim vertical space (the table used to start ~685px down; it now starts ~91px down).

```
.page (100dvh flex column, never scrolls)
├── header.bezel.bar          ← wordmark · portfolio picker · columns picker
│                               · add-ticker field · as-of field · status
│                               · Refresh · Export · ⋯ more menu
├── #readonlyNote / #fwdViewBar / .error    (flex: none, shown conditionally)
└── .table-bezel (flex: 1, min-height: 0)
    └── .table-wrap           ← the only scroll container on the page
```

- **The page itself does not scroll.** `body` is `height: 100dvh; overflow: hidden`; the table bezel is the flexible row and `.table-wrap` scrolls inside it. Never reintroduce a `max-height: calc(100dvh - Npx)` on the table — its height is derived from the flex column, so adding a notice steals from the table instead of pushing the page taller.
- **`.deck`** (add-ticker field, as-of field, status, Refresh) is `display: contents` on desktop, so its children join the bar's flex row directly. Below 768px it becomes a fixed full-screen glass sheet toggled by `#menuBtn` (a hamburger that morphs into an X, fixed to the top-right corner).
- **`.status`** uses `flex: 1 1 0` — a zero flex-basis makes it invisible to flex line-breaking, so it can never wrap a button onto a second line; it absorbs the slack instead. It's a **block** with `text-align: right`, not a flex row: a flex row justified to the end clips its *start* with no ellipsis.
- **The readout is a PILL, and the box is on a child (2026-09-26, owner: "the small green blink is hard to see sometimes").** It was 12px `--muted` text with a 6px pulsing dot, at the far right of a bar full of buttons. **The background cannot go on `.status` itself**: `flex: 1 1 0` means it is as wide as whatever the bar has left, so a background there paints a band across the slack rather than a pill round the words. `setStatus` builds a `<span class="pill">` inside it instead — inline-block, so the box is the size of the text, with its own `max-width: 100%` and ellipsis since the parent's cannot reach a child.
  - **STILL `textContent`, NEVER `innerHTML`.** Portfolio and theme names reach this function as free text (`added to "<name>".`), so an interpolated pill would turn the one status line into an injection point. The span is created and its `textContent` set; there is a test that drives a portfolio named `<img src=x onerror=…>` through it.
  - **AMBER IS SPENT, NOT DECORATIVE — which is why the badge is not permanently yellow.** In this app amber already means *notice this, it is old*: the Price pulled column past a day, the Turso usage bar past its threshold, the studio's freshness line past 26 hours, the alerts real-time panel. A badge that is always lit stops being read within a day and would leave nothing to say a reading is genuinely stale. So the **box** is the visibility fix and the **colour** keeps its job: green and pulsing while current, amber and still once past `STATUS_STALE_MS` (26 hours, the studio's own threshold reused). The pulse stops deliberately — a pulse says something is arriving, and nothing is.
  - **A bad timestamp reads as FRESH.** `Date.now() - new Date(x).getTime()` is NaN for an unparseable value and `NaN > x` is false, which is the right way round for a badge whose amber is supposed to mean something.
  - Verified: **32 checks** measuring what is DRAWN — the background's alpha, the border, padding against the text's own range rect, the box hugging the text rather than spanning the slack (239px of 691 available), the colour brighter than the `--muted` it replaced, both dot colours, the pulse stopping, and **26 hours probed at 25 and 27** since a threshold is a step function. **Proved by reverting**: stripping the box styling fails 4.
  - **The two bar invariants are asserted, because they are what a taller or wider status would break**: every child of `header.bar` still starts on ONE line, and the bar's height is identical with the pill shown and hidden (104px either way).
  - **The phone assertion measures the pill's own contribution (nothing) rather than an absolute zero**, because on the screener `scrollWidth` is never zero-overflow — see the entry below, which corrects what this line first claimed.

#### `scrollWidth` IS THE WRONG QUESTION ON THE SCREENER (2026-09-26)
**Reported by me as "27px of sideways scroll at 390px", then asked to be fixed, and on investigation there is nothing a user can reach.** Worth writing down because the wrong measure is the obvious one and I shipped it in a test and in this file.

- **`document.documentElement.scrollWidth - clientWidth` is 105px at 390px, and the page still cannot be panned.** `body` is `overflow: hidden` here (the flex-column layout: the page never scrolls, `.table-wrap` does), and **`overflow: hidden` still permits SCRIPTED scrolling** — `window.scrollTo(200, 0)` really does move `scrollX` to 105. So a `scrollTo` probe, and `scrollWidth` itself, both report a page that no finger and no wheel can move.
- **The honest test is a gesture.** `page.mouse.wheel(300, 0)` leaves `scrollX` at 0. That is what a person can do, and it is refused.
- **What overflows is by design or invisible.** The table (`right=5529`) lives inside `.table-wrap`, the page's one scroll container. Everything else past the edge is a **closed** `.picker-menu` — `visibility: hidden`, `left: 0`, `min-width: 236px` on a trigger near the right edge; `placeMenu()` clamps a menu when it is OPENED and nothing clamps one at rest, which does not matter while it cannot be seen or reached.
- **`.picker-menu` exists on `index.html` and nowhere else**, which is the one page with the body clip — so the containment is not luck, and there is no second page where the same pattern leaks.
- **Left alone deliberately.** The candidate fixes all cost more than the number is worth: collapsing a closed menu's width makes it reflow visibly through the 0.45s open transition, `overflow-x: clip` on `html` risks the fixed grain/aura layers and the mobile sheet, and a static right-anchor is the thing `placeMenu` exists instead of. **On this page, assert that a wheel gesture moves nothing — never that `scrollWidth` equals `clientWidth`.** Every other page's `scrollWidth` assertion is fine, because those pages genuinely have no overflow.
- The bar stays on one line down to ~1280px; below that it wraps, which is intended.
- **`#tableLoading` says why the wait is happening, not just that it is (2026-09-18).** An overlay on the table bezel — spinner, "Loading the screener…", and a line underneath — shown only while `baseStocks` is empty, so a poll-driven reload never blanks a table in use. Before it, a slow first load was an empty table, a progress cursor and the word "Loading…" in the far-right status. **The explanation comes from the cheap endpoint racing the slow one**: `/api/status` stays ~0.15s while `/api/stocks` is minutes-slow on a cold instance, so it is asked in parallel, and a refresh in progress both fills the line (with its `loaded/total`) and raises `#refreshBar` *during* the wait rather than after `/api/stocks` lands and the answer no longer matters. Nothing running and five seconds gone says the server may be starting up; that timer is deliberately **not** cleared in a `finally`, since a prompt "nothing running" is the signal to keep waiting.
  - **It is an OVERLAY, not a row, and that is the point.** The first cut was a `<td colspan="91">`, and `text-align: center` centres across ~3,300px — on a 1,440px screen the block sat off to the right where nobody saw it, while the assertion calling it "in view" tested only the vertical position. A screenshot found it. **Check both axes when asserting that something is visible in this table.** `showLoading()` (the Refresh all progress line) still spans, and takes `PAD_SPAN` — its colspan had been stale at 51 since the table was 51 columns wide.

### The quick stock finder (2026-09-29, owner's request)
**A `Find a stock` box at the head of the bar: type a ticker or a company name, press Enter, and that stock's page opens.** The owner's words were *"a quick stock filter when someone is trying to find info for a single stock"*, and the three readings of that were put to them — narrow the table to it, jump to its row in place, or open its page. **They chose the page**, which is the one the other two cannot do: the row answers *how does it compare*, `/stock` answers *tell me about this company*.

- **NARROWING ALREADY EXISTED and is untouched.** The filter row's Symbol box does exactly that, and the Sector and Industry cells do it for their own values — so this deliberately does not duplicate it. What was missing was a fast path to the one page that holds the chart, the filings, the earnings, the peers and the short interest.
- **IT SEARCHES THE UNIVERSE, NEVER THE ROWS ON SCREEN, and that is the whole feature.** You reach for it *because* the stock is not in front of you — the tab, a sector cut or a column filter has taken it off the table. It reads `baseStocks`, the page's own unfiltered copy, so it also costs **no request**. The test narrows the table to Technology and then finds a Healthcare stock by name; **proved by reverting**, where pointing it at `visibleStocks()` fails exactly that check and nothing else.
- **A PREFIX BEATS A SUBSTRING, then the bigger company leads.** Typing `mu` must not bury Micron under every name containing those two letters, so the order is: the symbol exactly, a symbol prefix, a name prefix, then anything containing it. **Within a rank it is market cap, not the alphabet** — `mic` puts Microchip, Microsoft, MicroStrategy and Micron in one band, and three letters means the one you have heard of. That is also the table's own default sort, so the finder is not ordering by a rule that exists nowhere else on the page.
- **A NEW TAB, which is the screener's standing rule for reaching a stock.** `.namelink` and the ticker link both carry `target="_blank"` so a click never loses your place in the list; a finder that navigated in place would be the one link here that does. The rows are real anchors, so a middle click or ctrl-click still works.
- **A stock with no data yet is never offered** — the rule `/api/stock`'s own picker already follows server-side (`stocks.filter((x) => !x.error)`). It has no page worth opening. The fixture's no-data row matches the query by symbol prefix, so it would sit *second* without the guard.
- **A GUEST IS ONLY EVER OFFERED WHAT IT CAN OPEN.** `/stock/:symbol` redirects a guest to `/` outside the twenty preview symbols, so a finder over the whole universe would hand every guest rows that bounce. It is safe automatically, because the rows it reads are narrowed server-side — and that is exactly the kind of "automatically" that stops being true when someone changes the source, so there is a walk that gives a guest a **two-symbol** preview and asserts the other two matches are absent and the offered one really lands on a stock page.
- **THE BAR IS TWO ROWS AT 1600px and this must not make it three.** Asserted as an **A/B on the same page** — measure, `display: none` the box, measure again, put it back — so the only difference is this control. Rows are found by **clustering** the tops of `header.bar > .core > *` (>14px apart is a new row), never by counting distinct values. Measured: 2 rows and 104px either way.
- **The input does not grow on focus**, deliberately: the bar is a flex row that already wraps, and a widening box reflows every control after it and can push the bar onto another row *at the moment of use*.
- **Escape clears what was typed before it lets go of the field** — the search-box convention — and the panel closes on an outside click and on a resize, since it is fixed-position and a resize would otherwise strand it pointing at nothing. `closeFind()` joins the global Escape handler beside `closePickers` / `closeMyPop`.
- **The table's own arrow keys are not disturbed**: that handler already exempts `input, textarea, select, [contenteditable]`, and there is a check that ArrowRight inside the box does not scroll the table sideways.
- **No keyboard shortcut**, the owner's call when offered one — `/` and ctrl+K are both still unbound anywhere in `private/`, if that ever changes.
- Verified: **34 checks** on the real page plus **6** on the guest walk. **The fixture is the test**: every row contains "mu" in a different position (exact, symbol prefix, name prefix, name substring, symbol substring) and **MU is deliberately not first in the universe's own order**, so a finder that does no ranking leads with the wrong company rather than passing by luck. **Proved by reverting five times**: the on-screen rows fail 1, dropping the ranking fails 7, dropping just the cap tiebreak fails 1, dropping the no-data guard fails 1, and not closing on resize fails 1.
  - **Two fixture faults worth keeping.** "Super Micro Computer" and "Cummins" were the first name-match rows and **neither contains the letters "mu"** — the suite reported the code wrong when the fixture was. *Check the string, not the impression it gives.* And the sector filter is cleared with `setSectorFilter('All')`, never `''`: the empty string is a real value that matches no sector, so the table emptied and an unrelated check failed.

### Dropdown menus
Four menus share one controller. Only one is open at a time.

| id | trigger | contents |
|---|---|---|
| `#picker` | portfolio name + count | All + every portfolio + "New portfolio" |
| `#colPicker` | `Columns n/10` | multi-select column groups + Show all / Hide all |
| `#researchPicker` | `Research` | Analysis, Strategy, Single + the three per-symbol pages |
| `#morePicker` | `⋯` (anyone signed in) | Delete portfolio (admin, contextual), Help, Contact, Change password, Sign out |

**One admin door, not a dozen (2026-09-14).** Everything that was not a description of the table in front of you moved to **`/admin`** (see **The admin console**), and the bar now carries a single `Admin` link for the owner. Gone from it: the Weights picker, the Research picker (for the owner), the forward-returns calendar, the add-ticker panel, Refresh, Refresh all, the Visitor and Activity icons, and the Users / Promo rows in `⋯`. What is left describes the view. Nothing depends on the order — no sibling or positional selector in either stylesheet touches these, and no script walks the bar's children — so **reordering really is moving markup**, and that was re-verified rather than trusted when Table/Tiles moved.

- **Order as of 2026-09-26** (owner): **Table/Tiles** (with Per row and Range, which are its own controls), **View**, Screens, Theme, Sector, Industry, Size, Advice, Advice move, Filter, Promo Studio, Pivot view, Compare, then the status pill, Ask, Alerts, Admin and `⋯`. Layout came after View until then; which SHAPE the rows take is the coarser choice. **The three tile controls travel WITH the toggle** — Per row and Range belong beside the thing they configure, and leaving them put would have parked the View picker between them.
- **THE BAR IS TWO ROWS AT 1600px, and the "one line down to ~1280px" note above it is long stale** — it predates about a dozen controls. Measured 2026-09-26. Do not write an assertion that the bar is one line; assert that a change does not ADD a row, ideally as an A/B on the same page (move the markup back with `insertBefore`, measure, move it forward again — same window, same fonts, same controls, so any difference is the order and nothing else).
  - **`header.bar > *` IS ONE ELEMENT — the `.core` wrapper.** An assertion shipped an hour earlier counted its tops and "proved" the bar was on one line over a single box. The controls are `header.bar > .core > *`, and **they sit at slightly different tops within a row**, so rows have to be found by CLUSTERING the tops (>14px apart is a new row), never by counting distinct values.
  - **A closed `.picker-menu` keeps its box.** It is hidden with `visibility`/`opacity`/`transform`, never `display: none`, so a `getBoundingClientRect().height` check reads a shut menu as open — ask `.picker`'s `data-open`. And **visibility transitions over 0.45s**, so a 300ms wait after Escape still reads `visible`.
- Verified: 20 checks driving the real screener — the drawn left-to-right order, the A/B on rows and height, the toggle still switching to tiles and back, Per row and Range landing between the toggle and View, and the View menu still opening, staying clamped inside the window and closing.

- `openPicker(id)` opens one and closes the rest; `closePickers()` closes all. They close on outside click, Escape and resize.
- `placeMenu()` clamps an opened menu inside the viewport — it shifts left of its trigger rather than overflowing, and never crosses the left gutter. Don't replace it with a static `left`/`right` anchor; no single anchor suits both triggers at every width.
- `#morePicker` holds the *real* buttons (`#renameBtn`, `#deleteBtn`, `#changePwBtn`, `#logoutBtn`) restyled as `.pick` rows, so their existing listeners and disabled-state logic still apply. `#portfolioActions` and `#sessionActions` wrap the contextual rows with their separators so both hide together.
- **`#researchPicker` is `member-only` now** — it is a member's only way to the research pages, and members cannot open `/admin`, which carries the same list for the owner. `applyAdminUI()` hides it for the owner and the guest branch still hides it for guests, in that order.
- **`#researchPicker` ("Research") holds every page that studies the data** — Analysis, Strategy and Single, then a separator and the three per-symbol pages (Stock, Signal study, Indicator lab). It replaced four separate labelled buttons in Sep 2026: the bar already carried six pickers and eighteen buttons and wrapped below ~1280px, and four nav buttons was the largest block that could become one.
  - **The three per-symbol rows open whatever is on top of the current view.** `researchSymbol` is set from `sorted[0]` in `render()`, not from the ranking, so it follows the sort and the portfolio filter rather than quietly always meaning rank 1. All three destinations carry their own symbol picker, so which one it lands on matters little — the point is not having to hunt for a name to click first. The menu names the stock it will open, because a link whose target moves should say where it is going.
  - **With no rows at all the per-symbol half is replaced by a line explaining why**, rather than three links to `/stock/undefined`.
  - **It uses `we()`, the page's top-level escaper.** The only `esc` here is scoped inside the CSV export — see the warning below; this is the third function that would have tripped over it.
- **Ask and Admin are the only top-level link buttons left.** Refresh, Refresh all, the logs and the studio are rows on `/admin` now.
- The column menu is rebuilt by `renderColumnMenu()` from inside `applyGroups()`, so the trigger count can't drift from the table state. It deliberately stays open while you toggle.
- **Each menu row also carries a jump arrow** that scrolls that group into view — 47 columns across ~3,300px is more than a scrollbar should be asked to do, and the groups are how anyone thinks about the table anyway. The toggle and the jump are siblings in a `.pick-row`, because a button cannot nest inside a button. The arrow is disabled while its group is collapsed.
- **`scrollToGroup()` works from `getBoundingClientRect()` plus the current `scrollLeft`, never `offsetLeft`.** A table cell's `offsetParent` here is `main.page`, not the table, so `offsetLeft` overstates by the table's own inset and lands the group ~29px *underneath* the frozen columns. It also subtracts the frozen block's measured width, or the target hides behind Symbol and Name.
- **Arrow keys scroll the table horizontally**, shift for a page, home/end for the ends — the hint at the foot of the columns menu is where they are advertised, since Shift+wheel already works natively but nobody knows. The handler ignores keystrokes aimed at an input and does nothing when there is no horizontal overflow.
