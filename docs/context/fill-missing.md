## Fill missing — the incremental refresh
**`Fill missing` on the admin console's Data section re-pulls only the stocks whose company data is missing (2026-09-15).** Same round loop, banner and report as Refresh all; the difference is which profiles are expired at the start.

- **What counts as missing — `profileGaps()`**, in order: no stored profile (`none`, a new ticker); a stored profile **lacking a key** the app now writes (`fields`); a pull refused or never finished (`failed`, fetched_at 0). **Old is not missing** — that is the rotation's job and Refresh all's.
- **Absent, not null, is the test, and it is load-bearing.** `emptyProfile()` is the literal `fetchProfile()` starts from, and `PROFILE_FIELDS = Object.keys(emptyProfile())`, so every pull since a field was added carries its key even when the provider has no value. A fund pulled since 2026-09-14 has `industry: null` and is left alone; a naive "industry is blank" test would re-pull SMH, XLF, KRE and CYBR on every run and buy the same null. Measured before building: 115 profiles lacked the `industry` key (Cisco and Netflix among them — pulled the morning of the 14th, before the field shipped), 4 had it null. Adding a field to `emptyProfile()` is therefore all it takes to make the next Fill missing backfill it.
- **Prices**: none by default — `POST /api/refresh-all?mode=missing` stamps `prices_at` at once and every round is an archive round (7 profiles, 561 credits). The exception is a stock with **no bars at all**: `liveRefreshOpts()` gives a `mode: 'missing'` run one price round of exactly those symbols, then `notePriceRound` stamps `prices_at`.
- **State**: `refresh_state.mode` (`'missing'` or null). **`beginRefresh()` now also resets `prices_at` and `priced`** — it upserts onto a possibly stale row, and before this a row left by an abandoned run could tell the next run its prices were already pulled.
- **`GET /api/refresh-missing`** (admin) is the costed preview and changes nothing: the console shows it under the button ("115 of 271 stocks — 115 pulled before a field existed (industry). About 17 rounds, ~17 min, ~9,217 credits") and repeats it in a confirm; with nothing missing the button says so and does not navigate. The POST answers `{nothing: true}` in that case and the screener says so instead of starting.
- **The nightly job fills gaps first**: on a rotation night the cron `?start=1` expires the gaps before `expireOldestProfiles()`, which only picks among fetched_at > 0, so gaps are not counted against the rotation. A new ticker or a new field fills the next night.
- **The report** is titled *Fill missing* and adds "Still missing" (a fresh `profileGaps()` after the run) and "No industry from the provider (expected for funds)".
- **Credits are a pacing unit, not a budget**: Pro has no daily cap (`/api_usage` returns only `plan_limit: 610` per minute — a Basic key also returns a daily limit).
- Verified: the preview on live data (115 gaps, 17 rounds); a vm simulation of the real `profileGaps` / `missingPlan` / `liveRefreshOpts` / `notePriceRound` over an in-memory store (17 checks — only the 115 gaps re-pulled, 17 rounds, max 561 credits/round, a new ticker priced alone in round one, a normal Refresh all and a plain Refresh unchanged, null industry not a gap); headless page runs of the console preview + confirm, the screener's `?do=refreshmissing` run, and the nothing-missing path.
