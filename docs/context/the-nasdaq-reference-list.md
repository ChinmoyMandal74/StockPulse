## The NASDAQ reference list
**`/nasdaq` (admin only, linked from the console's Reference section) — every US listing NASDAQ publishes, in its own table, joined to NOTHING (2026-09-14).** It exists so a candidate ticker can be *found*; adding one to the screener is still a deliberate act, and the owner's instruction was explicit: do not mix this with the screener.

- **Why it exists at all.** Twelve Data will not sell this on the Pro plan at a sane price, measured rather than assumed: `/stocks` is free and lists 16,399 US common stocks but carries **no market cap**; `/profile` (10 credits) has sector, industry and employees but **no cap field either**; `/statistics` (50 credits) is the only Pro source of `market_capitalization` and **does not batch** — `symbol=AAPL,MSFT` returns 404 and still charges 50. Sweeping NYSE + NASDAQ (5,747 names) would be **~287,000 credits and about eight hours** at the 610/minute ceiling. There IS a `/market_cap` endpoint at **1 credit**, and it is **Ultra-only** — it answered for AAPL and 403'd for MSFT and NVDA, the free-sample-symbol trap this file already warns about, caught a second time.
- **The source**: `api.nasdaq.com/api/screener/stocks?tableonly=true&limit=25000&download=true&exchange=<EX>`, free, keyless. All 12 published fields are stored plus the exchange, which the API does not return and the *request* therefore supplies — three calls, NASDAQ 4,131 + NYSE 2,710 + AMEX 295 = **7,136 rows**, of which **4,344 clear $100M** and 398 carry no cap at all.
- **The User-Agent is load-bearing and the failure mode is nasty.** Given a bot-shaped agent the endpoint does not answer 403 — **it never replies at all**. Measured: an honest `TickrLab/1.0` agent hung until a 20s abort; a browser-shaped one answered 200 in 296ms. So `NASDAQ_TIMEOUT_MS` is not belt-and-braces, it is what stops a serverless function sitting on its hands until the platform kills it.
- **One exchange per request**, `POST /api/nasdaq/refresh {exchange}`, driven three times by the page — the Refresh-all shape. Measured server-side: AMEX 0.3s, NYSE 1.0s, NASDAQ 2.7s, so the split is comfortable rather than necessary. Each exchange is a wholesale replace, which is how a delisting leaves.
- **`{ ...row }` on a libSQL Row gives POSITIONAL keys.** The first read shipped `{0: 'AAPL', 1: 'NASDAQ', …}` and every field on the page read `undefined`; named access works, spreading does not. Accessors here build the object field by field.
- **`url` is stored but never shipped** — all 7,136 are exactly `/market-activity/stocks/<lowercase symbol>`, checked, so the page derives it and the payload drops 277 KB. What is left is ~2.0 MB, ~370 KB gzipped, fetched once for an admin page that then filters in the browser.
- **The page marks rows already in the screener** (`held`, from the universe in `/api/portfolios`, NASDAQ's `BRK/B` matched as `BRK.B`) and can filter them out, which is the actual workflow — hunting for what you do not have. **Only symbols flow the other way, and only when ticked** (see below); no NASDAQ value — cap, sector, price — is ever written into the screener.
- **Paste a batch on `/admin` instead (2026-09-18).** The `/nasdaq` table is for FINDING a ticker; when you already have a list, hunting each one through 7,136 rows is the wrong shape. `Add many at once` takes commas, spaces, newlines, `$TSLA`, `brk/b` and lowercase, deduplicates, and **puts the whole batch in one portfolio — creating it if it does not exist**, which the bulk API refused before (`Portfolio not found`).
  - **Creating takes an explicit `createPortfolio: true`**, and the page confirms out loud first. A typo in a batch would otherwise leave a junk list behind with every stock quietly inside it. The name matches **case-insensitively**, like `POST /api/portfolios`: typing `chips` when `Chips` exists lands in the existing one rather than making a second.
  - **Free text splits into symbol-shaped tokens, and that is the real hazard.** `not a ticker!` becomes NOT, A and TICKER — and **A is Agilent**, so neither length nor shape can tell a batch from a sentence. `POST /api/universe/check` seeks the pasted symbols against the stored NASDAQ listing (`symbol` is the primary key, so N seeks, never a scan) and the preview says *2 not in the NASDAQ listing (NOT, TICKER)* in red. **It was advisory and is a GATE since 2026-10-03** — see **The Check button refuses what the provider cannot price** below. The listing half stays advisory (a legitimate foreign listing may simply not be in NASDAQ's file) and is now a footnote: that table is EMPTY in production, so it was advisory about nothing.
  - **No API call at add time** was the owner's instruction and the behaviour until 2026-10-03, when the owner asked for the opposite — the add now costs **1 credit a symbol** to ask the provider whether it can price it at all. That rule was about the **81-credit profile pull**, which is still deferred: names come from the stored listing, so adding is near-free and instant and the data arrives with Fill missing. The preview quotes the cost (~81 credits a stock, 7 a minute) before you commit.
  - **`input[type="text"]` was uppercasing the portfolio name.** The rule was written for the ticker box; it is `#sym` now. The third selector this day written for one element and caught by a later one, after `.warn` and `.card` — **a style rule that is not scoped is a trap with a delay on it.**
- **Bulk add (2026-09-15, owner's choice of the bulk-import options).** A checkbox column (held rows and `^` preferred shares disabled), a header box that selects every MATCHING row in sort order (not just the drawn page), and a selection bar: count, the data-pull cost (~81 credits a stock, 7 a minute of Fill missing), an optional "Also add to <portfolio>", Add. `POST /api/universe/bulk {symbols, portfolio?}` (admin, ≤ `BULK_ADD_MAX` 500): `/` → `.`, `SYMBOL_RE`, dedupe; answers `{added, already, invalid}` plus the universe. **Names come from the listing** (`cleanListingName` strips "Common Stock", "Ordinary Shares", ADR tails), only where none is stored — **so adding costs no credits**; the data arrives with Fill missing (the done bar links `/refreshes?do=refreshmissing`) or the nightly gap fill. **Read the universe BEFORE the portfolio write** — `writePortfolios()` inserts members into the universe, and reading after it reported every new stock as "already there" with no names; caught by the test. A symbol the data provider does not know shows as an error row after the pull and stays a Fill missing "failed" gap until removed. Verified: API caps/404, and the page in headless Chrome against the real server on an in-memory database (23 checks — disabled rows, BRK/B matching, cost line, portfolio add, names trimmed and never overwriting, select-all capped and filter-respecting, held after add, no page errors). Its sector and industry columns are labelled *(NASDAQ)* because they are a third taxonomy agreeing with neither GICS nor the Twelve Data values on the screener.
