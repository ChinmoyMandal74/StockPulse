## Activity logging
**Who did what, fact-only — the `activity` table** (`ts`, `user`, `kind`, `detail`, `ip`), separate from `visitors` on purpose: that one is the anonymous front-door knock, this one is a known account doing a thing. Facts, never content — a chat row says `asked`, not the question. Viewed at **`/activity`** (admin only, linked from the bar and from `/visitors`), which shows per-user and per-kind rollups plus the filterable 500-row tail, and carries a **Clear log** button (`DELETE /api/activity`, confirm-with-count like the visitor one). Pruned to `ACTIVITY_KEEP_DAYS` (60) during every refresh, fire-and-forget.

- **Two halves.** Server routes call `logAct(req, kind, detail)` (fire-and-forget, never blocks the action): `page` (every gated page, symbol included), `login` (password / account / signup / guest), `chat` `asked`, `refresh` (plain / all / as-of — a Refresh All logs ONCE at its POST; its `?refresh=1` rounds are skipped via `opts.running`), `portfolio` CRUD, `model`, `contact`, `account` (logout / password-changed / reset). The client half is **`private/track.js`** (`window.track(kind, detail)`), loaded by the screener and the stock page for what the server never sees: `sort`, `tab`, `picker` (columns / weights / past / rules), `export` (the CSV is fully client-side), `panel` (ladder opens), `chart` (ranges, MA / RSI / Mom / Trend toggles, why-card).
- **The beacon batches** — events queue and flush as one `sendBeacon('/api/activity')` every ~20s, on a full queue and on `pagehide` — so a sorting session is one Turso write, not thirty. `POST /api/activity` (any signed-in user, guests included) allowlists the six client kinds (`CLIENT_ACT_KINDS`), clamps details to 80 printable chars and caps a batch at 50, so it cannot become free-form storage — the prefs-PUT rule.
- **Guests are the point.** The shared `st_guest` token cannot tell two guests apart, so the guest door also sets **`st_gid`** — a random id used ONLY as the log key (`guest-<id>`), kept if already present so a returning guest stays one trail. Deliberately noise-free: no `/api/status` polls, no sparkline/news fetches, no hovers, no refresh-all rounds, no cron.
- Verified on introduction with an admin walk + guest walk against a local boot: junk kinds dropped, oversize details clamped, guest 403 on GET/DELETE, anonymous 401, clear removed all rows.

### How long each operation took — `activity.ms` (2026-09-20)
**Every row can carry a duration, and `/activity` reports the spread per kind.** Asked for after a day spent finding slow paths blind; the summary is the half that earns its place, since a column of milliseconds down a 500-row tail is not something anyone reads.

- **WHOSE CLOCK depends on the kind, and there is deliberately no second column saying so.** The client kinds (`sort`, `tab`, `picker`, `panel`, `chart`, and the new `load`) are measured in the browser and are **what the person actually waited** — network and paint included. Every other kind is the server's own elapsed time, from a `req._t0` stamped by the first middleware. One rule read off the kind, in db.js and on the page, rather than a flag that can drift from it.
- **`page` is deliberately untimed, and the page says so.** Those rows are written at the TOP of their route, which then serves a static file, so the elapsed time is ~1ms every time: true, useless, and enough to drag the whole summary into nonsense. A page's real cost arrives separately as a browser-measured **`load`** row. `window.trackLoad(name)` reports it, and **the page decides when it is usable** — the screener calls it after its first render, not on `window.load`, which fires while `/api/stocks` is still in flight.
- **The duration rides on the EVENT, not the flush.** A beacon carries up to fifty events and the server stamps them all with ONE timestamp, so nothing downstream could ever recover how long a single interaction took. `track(kind, detail, ms)` is the only place that knows.
- **Reject the empty before coercing — the third time this codebase has needed that sentence.** `Number(null)` and `Number('')` are both `0` and finite, so the obvious ordering stores a fabricated `0ms` for every untimed event and puts a floor of zeros under every percentile, flattering it. Untimed is `null`; a *genuine* zero is kept and renders as `0ms`, distinct from the `—` of untimed. Browser input is clamped to `0…ACT_MS_MAX` (10 min) like any other untrusted field.
- **Exact sample percentiles in JS, not SQL**: one bounded read of `(kind, ms)` over a table already pruned to 60 days, the same reasoning the other `/activity` rollups use. **A p95 at n=5 lands on the fourth value** — that is what the statistic means, not a bug, which is why `n`, a `thin` marker and the slowest all sit beside it and the note says a p95 needs a few dozen observations.
- Verified: 33 checks against the real server and the real page — every coercion trap above, the cap and the clamp, an un-allowlisted kind refused, the rollup's median against a skewed sample where a mean would disagree, `page` untimed, and **the Took cells measured by `getBoundingClientRect()` rather than by their markup** (the `/quality` lesson: a style attribute can be perfect while nothing is drawn).
- **Two of the three failures in the first run were the test's own**: a p95 asserted against fixture noise from an earlier block, and a case-sensitive regex against headers that CSS upper-cases. The third was real — a lost backslash in a patch script left `a page's` terminating a JS string, which took the whole page down. **`node --check` on the extracted `<script>` block is how to catch that in an HTML file.**
- **It exposed one pre-existing layout bug**: `.island` is a single non-wrapping flex pill whose buttons already overran it by ~10px at 390px, invisible until the new panel made the page tall enough for a scrollbar to claim that width. The Clear log label takes `hide-sm` like its neighbours.
- **Unrelated and pre-existing, found while regressing this**: `views-test.js` and `screens-test.js` in the scratchpad both die with `window is not defined` — confirmed identical at HEAD with these changes reverted. `filter-test.js` was broken the same way and is fixed here: `visibleStocks` was split into `scopedStocks` / `prefilterStocks` / `activeColFilters` by the filter-row commit (2bc163a) and the harness was never told.
