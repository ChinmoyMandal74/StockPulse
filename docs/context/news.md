## News
Per-stock headlines — **headline / source / url / timestamp only, never bodies** — from a swappable provider in `news.js` (the barmath.js shape: parsing and selection pure, orchestration in server.js). Default provider is **Google News RSS, keyless**, queried by company *name* ("<name>" stock) because Google is not ticker-tagged — expect occasional neighbour-stock noise in a feed; `FINNHUB_API_KEY` switches to Finnhub's ticker-tagged `/company-news` (free tier: 60 calls/min, personal use), and `NEWS_PROVIDER=off` kills the feature (routes serve empty, pages show quiet states).

- **Storage**: `news` (id = url-hash, per-symbol, kept to 21 days / 25 items) + `news_state` (per-symbol fetch clock, separate so an empty feed still counts as fetched). Both in `SYMBOL_TABLES`, so a dropped ticker takes its headlines along. Writes are one batch per symbol.
- **HEADLINES ACCUMULATE; they are not replaced (2026-09-22).** `writeNews` opened with `delete from news where symbol = ?` — the whole-collection-replace that is right for portfolios and profiles, where the stored set IS the source of truth. A news feed is not that: Google News RSS serves a rolling window of the last day or two, so every fetch threw away everything older than the provider currently happened to carry. **Measured on production before the change: NVDA, MU and AAPL each held headlines spanning ONE OR TWO DAYS**, against a nominal 21-day window and a 25-item cap that could therefore never bind. Nothing older than a couple of days had existed at any point.
  - The id is a hash of the url, so `insert or replace` already dedupes an item the feed keeps serving; the wipe bought nothing. Two trims bound the table in its place: the 21-day cutoff that was always there, and a **newest-25 cap** — needed now, because `MAX_PER_SYMBOL` was only ever applied to the incoming batch and a stored set would otherwise drift past it over three weeks. Both seek on `idx_news_symbol (symbol, published_at)`; verified against `explain query plan` by hand, since the subquery is one the plan test cannot prepare.
  - **THE 25 WAS THE WRONG NUMBER, and it was the wrong KIND of number.** `MAX_PER_SYMBOL` is the dedupe cap on ONE FETCHED BATCH — the provider's page size — and reusing it as the retention ceiling truncated a heavily-covered stock to roughly a day's worth. `KEEP_MAX` (150, `NEWS_KEEP_MAX`) is the ceiling now, and it is only a guard against a runaway feed: **the 21-day window is the policy**. Worst case at 845 symbols is ~127k rows against 1.8M bars. Provisional, because nothing accumulated before 2026-09-22 and how fast a busy symbol fills is not yet measured.
  - **`/api/news` is PAGED** (`limit`, `offset`, and `total` on the response), defaulting to `NEWS_PAGE` 10. It served `readNews(symbol, 12)`, which is where the "12 items" in every reading came from — a number chosen when a symbol never held more than one fetch. Serving the whole set instead was fine at 25 a symbol and is not the shape to keep once a few hundred can accumulate: neither the payload nor the page's DOM should carry all of them to show ten.
  - **The stock page fetches a page at a time.** *Show more — 10 of 43* asks for the next `offset`; appends are de-duplicated by url, because a headline arriving between two requests shifts the window and would otherwise appear twice. An empty page ends the run whatever `total` claimed. *Show fewer* folds back to one page but KEEPS what was fetched, so re-expanding costs nothing. A list at or under one page grows no button.
  - **Nothing can be backfilled.** The provider only serves its current window, so accumulation starts from this deploy; the weeks before it are gone.
  - **A consequence worth knowing**: the News column's 7-day count badge could only ever count what the last fetch returned, so it had been understating coverage since it shipped.
  - Verified: 23 checks. The load-bearing one is the SECOND FETCH — items from the first must survive a fetch that no longer carries them. Plus dedupe on a repeat, both trims, the newest kept rather than the first to arrive, and the page's fold measured by `getBoundingClientRect()` rather than by class.
  - **Harness trap**: `uni-boot.js` defaults `NEWS_PROVIDER` to `'off'` to keep tests off the network, and the server then short-circuits `/api/news` to an empty list **before it reads anything** — so a news page test silently sees no headlines however many are stored. Set it explicitly.
- **News is its own button and rides NOTHING (2026-09-18, owner's instruction: "don't mix the news refresh with any API data refresh").** `POST /api/news/refresh` does ONE batch of the stalest stocks and says how many remain; the page loops it, the same shape the price refreshes use, because a serverless function must not be asked to hold hundreds of network fetches in one request. The button is on `/news-runs`, and the console's **Refresh news** row deep-links `?do=refresh` — the `/refreshes?do=` pattern. `topUpNews()` is deleted.
  - **Why it was moved.** It was awaited inside the refresh (nothing may run after a response on this platform), which put a dozen network fetches inside the request that also priced the universe and wrote the snapshot. On 2026-09-18 a refresh recorded its round at 78s, wrote a correct snapshot at 10:10, and was then cut before `finishRun` — logged **`abandoned`, with no error**, while the data was perfectly fine. The owner reported it as "price refresh failed again"; it had not failed. A refresh is one request and the tail was most of it.
  - **Staleness is the CLOCK, and the same test decides both what is picked and what `remaining` counts.** The first cut let "holds no headlines" make a stock stale, which is fine as an ORDERING boost (an empty feed is retried ahead of the rotation) and fatal as a termination test: a stock the provider has nothing on would be re-picked forever while the run reported itself done. Caught by a test that looped to completion and then asked for one more batch.
  - Batches log `trigger: 'manual'` with no `refresh_run_id`, so `/news-runs` no longer shows them as riding a refresh round. The stock page's own stored-or-fetch on a six-hour TTL is unchanged — that one is user-driven and costs nothing.
- *Superseded:* **Coverage without a schedule**: `topUpNews()` rides every refresh (each cron round included), topping up the `NEWS_TOPUP_PER_REFRESH` (12) stalest symbols, never-fetched first — the nightly job's ~20 rounds cycle the whole universe in one night. Started early in the round and **awaited before the response** — it was fire-and-forget until 2026-09-15, and on Vercel a function is frozen the moment it responds: batches were suspended mid-fetch, then every 6-second abort timer fired on the next wake, so two batches logged 54s and 279s with all 24 fetches "aborted due to timeout" for refreshes that took 19s. **Nothing may run after a response on this platform.** The batch still never rejects, so a failed news write never fails a refresh (the bars rule). `GET /api/news?symbol=` is stored-or-fetch with a 6-hour TTL so a visited stock page stays fresh regardless; on a provider failure it serves the stored set, stale beating nothing.
- **Frontends (deliberately only two)**: a News card on `/stock/<SYMBOL>` between the chart and the fields (ten headlines, escaped, http(s)-vetted links out, `target=_blank rel=noopener`), and one `News` row in the hover card's Info group — injected onto the rows by `loadLatestNews()` after the table paints (`GET /api/news/latest`, stored-only, one query — the sparklines rule), never a table column. The analysis page shows nothing because its rows never get `newsLatest`; `CHAT_FIELDS` still excludes news.
- Verified: 18 checks in the news suite (RSS entities/CDATA, publisher-suffix strip, dedupe caps, stalest picker, renderer escaping incl. a `javascript:` url refused), plus a live boot fetching real MU headlines through the whole path.

### The News column (screener)
**A News column in the Info group, and a panel behind it (2026-09-16).** Until now the only per-stock way in was hovering a row or opening its page; this makes the whole thing one click from the table.

- **The cell is the age of the latest stored headline** (`2h`, `4d`) with a **count badge** when the stock has more than one from the last week, brightened when the latest is under a day old. **Blank means two different things and the cell separates them**: an em-dash is "checked, nothing stored" with the tooltip saying when it was last checked, a faint dot is "not looked at yet" — headlines are topped up a dozen stocks per refresh round, so the second case is common and must not read as "no news". The latest headline is the cell's tooltip.
- **Sorting is on the timestamp, not the age**, because a new column starts descending and descending has to mean freshest first. Stocks with nothing stored sort last.
- **`GET /api/news/latest` now returns `{items, counts, checked}`** — the latest per symbol as before, a 7-day count per symbol (`newsCountsSince`, one bounded group-by over the pruned table: 5,849 rows on 2026-09-16, allowlisted in the query-plan test with that number) and `news_state`'s fetch clock. All three are guest-filtered. The screener already loaded this after the table painted for the hover card, so the column costs one extra small query, not a new request.
- **Clicking a cell opens `#newsPop`**: up to ten headlines with source and age, each opening the publisher in a new tab, plus a link to the stock page. It reads `GET /api/news?symbol=`, which is stored-or-fetch on a six-hour rule — so **a stock nobody has looked at gets its headlines on the first click**, at no API cost (the provider is free and keyless). Escape, an outside click or a resize closes it.
- **`?force=1` checks now** rather than waiting out the six-hour rule — the stock page's **Check now** button, beside a line saying when that stock was last checked. The provider is free and keyless, so a forced check costs no API credits; the server keeps a **one-minute floor per symbol** so a held-down button cannot hammer anyone, and a refused force answers normally with `forced: false` rather than an error. The route now returns `checkedAt` so the page can say "checked just now". Verified with the provider stubbed: 12 checks (no call inside the TTL, a call when forced, the headlines stored, the clock moving, the second force inside a minute refused, the button's states).
- Verified in a browser over four seeded stocks (fresh / old / checked-but-empty / never-checked): 15 checks — the endpoint's three parts, each cell's shape and tooltip, the panel's list with sources and links, the stock-page link, Escape, the "nothing stored" wording, and the sort order.

### The news ticker (screener)
**A slow crawl of headlines published in the last 12 hours, under the table (2026-09-15, owner's spec: slow, hideable, 12h then stale).** **It follows the table** — the owner first chose the whole universe, then changed it the same day: the strip shows only stocks `visibleStocks()` leaves on screen (portfolio, sector, industry, advice, advice move, column filters), the label reads "last 12h · stocks in view" while narrowed, and a view with no recent news says so in the strip rather than hiding it (hiding would resize the table on every filter change; the strip hides only when nothing in the universe is recent). **`render()`'s empty-table branch returns early, so it calls `paintTicker()` itself** — missed on the first cut and caught by the test. `GET /api/news/recent` reads stored rows only (`readRecentNews`, published_at ≥ now − 12h — ISO strings, so the comparison is lexical), keeps at most 2 per stock and one row per URL, universe-filtered and guest-filtered, and sends **every stock's share** (147 items / 70 KB at the time) — a universe-wide top 60 would leave most filters empty; the page takes the first 60 of what is in view. Item: `SYM ▲2.3% · headline · source · 2h`; the symbol opens the stock page, the headline the article (http/https only), both in a new tab.

- **`#ticker` is `flex: none` inside the page column**, so showing it takes ~44px from the table rather than growing the page; every visibility change calls `paintWindow(true)` because the windowed table sizes itself from `.table-wrap`'s height and no resize event fires.
- **Two copies of the items crawl by exactly one copy's width** (`translateX(-50%)`), so the loop has no seam; `--tk-dur` is set from the measured width at **60px/s**. Hover, keyboard focus and the pause button stop it (`animation-play-state`) — pausing moving content is a WCAG requirement, not a nicety. **Reduced motion gets no crawl**: one headline at a time, swapped every 6s with an opacity fade.
- **Rebuilt only when its items or the prices change** (`tickerKey` = urls + `lastUpdated`): `paintTicker()` runs at the end of every `render()`, and rebuilding the track restarts the crawl, so a sort or a filter must not. Re-read every 10 minutes, and the 12-hour window is enforced client-side too, so an item ages out between reads.
- **On by default; hiding is stored** (`prefs.tickerOff`, boolean-only in the PUT whitelist). The × on the strip hides it; `News ticker` at the top of the ⋯ menu toggles it back. Hidden when the window holds nothing.
- **Fixed first, because a ticker would have advertised it: news was searched by the quoted LEGAL name**, which matches mostly old filings that fall outside the 21-day window — 36 of 271 stocks held no headlines. `newsNamesFor()` now searches the display name (override, else `deriveShortName`), measured on all 36: legal-name queries found anything for 28 and stored nothing that survived the window; short names found 22-25 results for all 36, and at least as many for the control group. A stock holding no headlines whose fetch is past the TTL is now picked ahead of the rotation in `topUpNews`. **The short-name rule gained whole `American Depositary Shares` / `Sponsored ADR` / `N.V.` / `S.A.` tails** — 8 of 271 display names changed, every one a fix (AstraZeneca PLC American → AstraZeneca, Toyota Motor Corporation Sponsored → Toyota Motor, Adyen N.V → Adyen, NXP, STMicroelectronics, Spotify Technology, Ericsson, Nano Dimension); 14 rule cases pass.
- **Cadence caveat**: headlines are only as fresh as their last fetch — 12 stocks per refresh round plus stock-page visits. A 12-hour window therefore shows mostly the stocks fetched recently; the News runs page's coverage tile says how many that is.
- Verified: the filtered strip headlessly (11 checks — a sector shows only its stocks and all of them, a sort keeps the crawl, an empty table and a newsless view keep the strip with its message, one stock shows only its headlines, clearing returns to everything); the endpoint on live data (≤2 each, none older than 12h, no duplicate URLs; a guest saw only preview symbols); TM and AZN fetched through the fixed search (25 new headlines each, from nothing); a headless run on the real page over those headlines — 15 checks normal, 10 under `--force-prefers-reduced-motion`.

### The news log (`/news-runs`)
**Every batch of headline fetches is logged (2026-09-15)** — `news_runs` (one per batch) and `news_run_items` (one per stock in it), read by `/news-runs` (admin, a `News runs` row in the console's Data section). Two triggers: `refresh` (a refresh round's top-up, linked to the refresh run it rode on via `refresh_run_id`, whose kind the page shows — "Nightly round", "Fill missing round") and `page` (a stock page fetching headlines older than `NEWS_TTL_MS`).

- **`runNewsBatch(picks, meta)`** is the one path both triggers take: it logs each stock's outcome as it lands (fetched, **new** — not already held — and stored after the write) and closes the batch `complete`, `partial` or `failed`. **`writeNews()` now returns `{added, stored}`**, reading the symbol's prior ids and its final count in the same batch as the write, so the log costs no extra round trip.
- **`topUpNews` is called after `finishLiveRefresh` reads the run state**, so the batch knows its refresh run; it was the first line of the function before.
- **`abandoned`** = still `running` three minutes after starting (`NEWS_RUN_ABANDON_MS`). The top-up is fire-and-forget, and on serverless an instance can be frozen once the response has gone — this is the status that would show it happening. Swept lazily by every read.
- **The page**: coverage (last fetch under a day / under a week / older / never, the stalest stock, rounds for a full pass at 12 a round, provider), headlines stored (total, stocks with at least one, **stocks fetched but holding nothing**), the last 7 days (batches, fetches, failure rate, new headlines, batches that never finished), fetches per day for 14 days with new headlines as a line, filterable history, and a per-stock dialog linking to the batch's refresh run (`/refreshes?run=<id>` opens that run).
- **Retention**: 30 days of batches, 14 of per-stock rows, pruned after each batch.
- **First real reading, 2026-09-15: 36 of 271 stocks have been fetched and hold no headlines** (MS, RBRK, SKHY, BABA, CMCSA among them). The Google query is the quoted legal name + "stock", and a quoted "SK hynix Inc. American Depositary Receipt" matches nothing — the short name is the likely fix.
- Verified end to end locally: a stale stock page (EBAY, 13h) logged one batch — 25 fetched, 4 new, 25 stored, 668ms — and a second open inside the TTL logged nothing; route walk (anon/guest 302 and 403, admin 200, unknown batch 404); headless page over synthetic history.
