### The S&P 500 cut — eight promo templates and the pivot (2026-10-04, owner's request)

Everything below about the studio still holds.)*

**It cost one change on each side, and that is the point of both mechanisms.** `Cards.scopeOf()` is the one place every scoped card answers "which stocks?", reading `xxSector` / `xxIndustry` / `xxCap` / `xxScreen` off a per-template prefix — so `xxSp500` reached all eight templates at once, exactly as the size band and the screen cut each did. On the pivot the Filter picker is built from `DIMS` rather than from a list of its own, so one entry there became three controls.

- **NO SERVER CHANGE AT ALL.** `spMember` is one of the read-path stamps and **both** hosts already apply it — `/api/stocks` through `serveStamps`, and `/api/m/post` through its own line — so a saved post carrying the cut draws correctly on the phone without anything being wired. That was checked rather than assumed; the stamps are a set, and the set has been incomplete twice.
- **The cut is ORTHOGONAL, not narrower**: ANDed with the sector, the industry, the band and the screen, and named in the kicker *alongside* them (`Technology · S&P 500 · past week`) rather than replacing any of them. A posted card has no picker beside it, so the kicker is the only thing that can say which cut emptied it.

#### `=== true` AND `=== false`, NEVER TRUTHY — the whole guard in one line
`spMember` is **three-state**: null until a holdings file has been imported, and **null is not No**. A truthy/falsy test puts every unchecked stock in the "Not in the index" cut — which on an instance that has never run the import is the card stating that **all 1,278 of these are outside the S&P 500**, with confidence, in a picture somebody posts. The screener's own column refuses to give that answer and so does this.

- So on a no-file instance **both** cuts are empty rather than one of them being everything, and that reads correctly because the kicker names the cut.
- **An ABSENT field behaves like a null one**, which is not the same case: `serveStamps` catches per stamp, so a stamp that threw leaves the key off every row rather than setting it null. Both are checked.
- **Proved by reverting**: the truthy version fails exactly the two checks that matter, naming all ten fixture stocks in a cut that must hold none of them.
- The pivot takes the same guard from the other end: its getter is **`Filters.filterValue(s, 'spMember')`**, the one function that already knows the field is three-state and returns `''` for unknown — which `valuesOf` then buckets as the blank the page already draws and counts in its note. **Proved by reverting**: a `s.spMember ? 'Yes' : 'No'` ternary there labels a whole unchecked universe `No`.

#### Membership only — the weight never leaves `/holdings`
That page is `requireAdmin` because a reconstructed constituent list *with its weights* is the issuer's dataset, where a Yes/No for the stocks we happen to track is derivable from any financial website. The same line holds here: there is no weight on a card, no weight measure on the pivot, and a check that no card prints one.

#### The catalogue is the module's, so a host cannot offer a word the card ignores
`Cards.spCuts()` returns the three `[value, label]` pairs and the studio builds all eight pickers from it. A copy in the markup sending `yes` where `scopeOf` means `in` would filter **nothing and say nothing** — the silent-fallback class this module exists to keep out, and the reason `basketDays`, `evolutionNeed` and `themeClass` are exported too. **Proved by reverting**: hardcoding the options with `yes`/`no` fails 21 checks.

- Three values and no fourth. **"Unknown" is deliberately not offered as a cut**: it is a gap in our own data rather than a fact about a company, and a card captioned "stocks we have not checked" is not a card.
- A post saved before this existed carries no key, which filters nothing — checked, because that is every existing post.
- **No fourteenth listener list was needed and eight existing ones were.** A control in the markup and in `CONTROL_IDS` but not in its template's list saves with a post, is read by the builder, and **does nothing when you touch it**. Reverting the eight list entries fails 10 checks and reverting the eight `CONTROL_IDS` entries fails 13. The warning comment above them said "THESE EIGHT LISTS" while there were thirteen; it says "THESE LISTS" now, since a count in a warning is the thing that rots.

#### The instrument, and three ways it was wrong first

### The Size card — companies as concentric circles
**A tenth template (2026-09-20, owner's request): compare companies within a theme by size, carry other fundamentals with it, and do it as circles — "maybe two concentric circles, each representing a different measure".**

- **Both discs share ONE area scale whenever both are money**, which is what makes the pair worth drawing rather than decorative: the second disc's share of the first IS the ratio between the two figures. Clipping it would have hidden the most interesting case.
- **A RATIO has no scale of its own**, so a margin is drawn as a share of the outer area: 50% fills half the disc. Clamped at the edge, since a margin over 100% is a data fault rather than a bigger circle, and a negative one draws no core at all.

- **A THIRD measure rides as plain text under each circle** (2026-09-20, owner's request — "a third metric like P/E or Forward P/E, only as text, just to show the valuation difference"): forward or trailing P/E, P/S, P/B, EV/EBITDA, PEG or market cap. **Deliberately not a third ring** — the card already encodes two things by area, and a multiple is a number you read one company at a time rather than a magnitude you compare at a glance; three nested circles would be decoration pretending to be data.   - **Every multiple is the PROVIDER's own ratio, never one divided here.** Computing price-to-sales from a dollar market cap and a won revenue would produce a confident, meaningless number — the ADR trap this file records twice already.
  - **A multiple off a loss is arithmetic, not cheapness**, so a P/E at or below zero is a dash, never a negative number that would read as cheap. The same rule the Quality score and the fundamentals ranking apply.
  - **A dash means TWO different things and the caption separates them**: "1 had no meaningful multiple: a ratio off a loss is arithmetic, not cheapness. 1 does not report it." Drawing both the same and then counting one as the other is how a card quietly lies — the News column's and the data-quality page's lesson, met a third time.
- **A circle under 14px is floored AND MARKED** with a `·`, never silently enlarged: a dot drawn at its honest size is still the truth.
- **The cell is sized from the artboard's OWN height**, not the column count. A card cannot scroll — a grid too tall does not clip, it sits on top of the masthead, because `.s-body` centres its content. The first cut fixed the cell per column count and overflowed the SQUARE by 93px at four circles, the shortest artboard with the largest cells. The test sweeps 3 shapes × 5 counts × 3 inner measures and measures the artboard.

  - **`.s-in` is a fixed-height flex column, so its children overflow WITHOUT growing it.** Reading its `scrollHeight` answers "fits" while the body is spilling over the header. The honest numbers are **`.s-body`'s own overflow** and the gap between the kicker's box and the tagline's.

  - **It was NOT the third measure**, which is what I assumed and said out loud — it overlapped with that switched off too. `FURNITURE` was simply set below what the card takes: measured, everything above the grid is ~395px and below it ~197px, against a reserve of 530.

Tightest clearance 13px, zero overflowing.

### The Bubble card — two measures against each other, area as a third
**An eleventh template (2026-09-20, owner's request): "show the chart as bubble instead of concentric circles, or add a new template called Bubble".** Built as a new template rather than an option on Size, for a reason worth keeping:

- **A single circle per company ALREADY EXISTS** — Size with the inner measure set to none — so the option reading was very nearly a no-op. The reading worth building is the other one: a chart where **position** carries meaning. Size ranks magnitudes in a grid; Bubble asks how two measures relate and lets a third set the weight of each answer.
- **It is also not the quadrant card** (`fund` mode `quad`), which plots one FIXED pair — revenue growth against profit margin — with every dot the same size. Here both axes and the area are chosen, which makes it a different question rather than a restyling.
- **The measures are `FUND_METRICS`, exported as `Cards.bubbleMeasures()`** and used to build the studio's three pickers. Seventeen measures, one list: a copy in the markup would drift the first time one was added, and a test asserts the picker matches the catalogue exactly.
- **`plotScales` was extracted from `scatterSvg`** so the axis arithmetic — the middle-range span, the padding, the stray pinning — is not written twice. The quadrant card's own output is asserted unchanged afterwards, because a refactor that quietly rewrites a published chart is the failure to fear.
- **THE PERCENTILE TRIM DOES NOTHING AT SMALL n, which is why `fence: 'iqr'` exists.** The 2%/98% trim drops three dots at each end of the quadrant card's ~140 and behaves; at the 20 a Bubble shows, `floor(20 * 0.02)` is 0 and it trims **nothing** — so one company at 900% growth sets the axis, presses every other circle into a band a few pixels tall, and nothing is ever marked as pinned. Tukey's fence (a quartile either side, 1.5x the spread) is robust at any size and is what a small plot asks for.
- **A CIRCLE IS NOT A DOT, and two bugs came from forgetting it — both found by a screenshot, neither by an assertion.** Pinning a stray puts its CENTRE on the axis edge, which hung half of NVIDIA off the artboard: the biggest company on the card, sliced in two, *because* it was the furthest out. Centres are kept a radius inside the plot now. And labels anchored left or right of the mark — fine beside the quadrant card's 7px dots — printed "JPMorgan Chase" straight across Microsoft at 66px. A name sits **inside** its circle when the circle can hold it (the one thing a bubble can do that a scatter cannot), otherwise centred **below**; and a label that would land on one already placed is **dropped**, because an unreadable name is noise and hides the mark underneath.
- **AREA is the encoding, never radius**, checked against arithmetic rather than by eye: caps of 400/100/25 must give radii 1 : 0.5 : 0.25, where sizing by radius would give 1 : 0.25 : 0.0625. The card says so on its own face, because the misreading is the default.
- **The fundamentals guards travel with it**, and matter more here than on a ranking, because an axis is a comparison by construction: non-USD reporters are dropped from any money comparison (Samsung's revenue is in won), banks from gross margin and net cash, and loss-makers from a P/E or PEG axis. A company with **no positive area measure is drawn as a ring** at the floor size and counted in words — it still has a place on both axes, and either inventing an area or dropping it silently would misreport the screen.
- **A FOURTH measure rides as text, the Size card's own** (2026-09-20, owner: "also show as text, what you have done in the size chart"). Same catalogue (`SIZE_THIRDS`) and the same rules, now in one shared `thirdReader()` that both cards call — the provider's own ratio rather than one divided here, a **dash for a multiple off a loss** (arithmetic, not cheapness), and the **two kinds of blank counted separately**, because a company that loses money and one that does not report the figure are different facts and drawing them the same is how a card quietly lies.
  - **It rides the NAME, not every circle.** Twenty positioned, overlapping circles cannot each carry two lines of text without exactly the collisions the labelling rules exist to prevent. So it appears on the companies that are labelled — and the caption says **"Of the companies named, …"**, since a count over a subset must not be worded as a claim about the screen.
- Verified: 33 checks off-page (the area arithmetic, the guards, rings, pinning, each channel following its picker, an unknown measure key falling back, three artboards, the third measure's dash for a loss counted apart from an absent figure, money formatted currency-neutral, and the quadrant card unchanged) and 23 in the real studio, plus screenshots at true 1080px — which is what caught both drawing bugs.
  - **Two fixture traps worth keeping**: the loss-maker has to be big enough to be NAMED or its dash is never drawn and the count stays at zero; and `forwardPe: 8 + (cap % 40)` gave every company `8.0×`, a screenshot that showed the feature working and demonstrated nothing.

#### The saved-post option cap was silently eating controls

### The Evolution card — one company's filings over time (2026-10-04, owner's request)
**A seventeenth template, `evolution`, third in the studio's picker: two stacked panels on one time axis — what the business did, and what the market paid for it — plus a four-figure then→now row.** The owner's words: *"a new template called Evolution, that shows the evolution of Earning, P/E, Market cap etc for a stock using data from Edgar"*.

It reads **`sec_facts`**, so it is the first promo card sourced from the filings rather than from the snapshot or the bar archive. `GET /api/evolution?symbol=&years=` returns one trailing-twelve-month point per filed quarter — `SecFacts.ttmSeries` over `latestFilled`, the same rolling window the SEC card's own TTM row uses, so the newest point on the chart **equals** the figure on that card.

#### `sharesDiluted(t) × close(t)` UNDERSTATES NVIDIA'S PAST VALUE BY FORTY TIMES
**The decisive measurement, and the whole reason the card is shaped the way it is.** A filed share count is as-filed and **never restated for a split**; the bar archive **is** split-adjusted (`persistBars` detects a split and rewrites the symbol's history). Multiply the two together and every pre-split point is wrong by the cumulative split factor — NVDA's 4:1 of 2021 and 10:1 of 2024 compound to **40×**, which put its historical P/E at a **median of 1.0**.

- **The shipped formulation is `cap*(t) = sharesToday × close_adjusted(t)`**, which cancels splits **exactly**: an adjusted close is already quoted in today's share units. The residual error is net share issuance since *t* — slow, bounded, and directionally knowable, which is why the note says a buyback makes the earlier multiple read low.
- **Verified at the anchor, against production**: `sharesToday × today's close` beside the vendor's own market cap over twelve symbols — **8 within 2%, 11 within 3%**, worst **INTC at −5.1%**, where the diluted count and the outstanding count genuinely differ. (An earlier exploration note here claimed "±2% on 11 of 12"; that was a different sample and is corrected to what the live route actually gives.)
- **THE CARD'S LAST POINT IS PRICED AT ITS LAST FILED PERIOD END, NOT TODAY**, so comparing it with the screener's market cap measures the price move since that quarter and nothing else — measured, **NVDA +13.1% and AAPL +17.6%** at the time of writing. That is the calendar rather than the formula, and it is the first thing the next reader will mistake for a fault.
- **RECOVERING THE SPLIT FACTOR FROM THE SHARE SERIES WAS TRIED AND REFUSED.** It cannot be done cleanly: AAPL's 7:1 reads **×6.8389** and TSLA's 5:1 reads **×5.2090**, because buybacks move the count inside the same quarter and the filed dates straddle the split — and NVDA's own trail carries a junk row (564.5M → 0.5M → 582.6M, a **×1017** "jump") that any threshold would mistake for one.
- **Proved by reverting**: the naive formulation prints **$77.7B where the truth is $310.6B** on the fixture — exactly a quarter of it, the 4:1 split — and fails 5.

#### Why two panels rather than two rebased lines
Rebasing needs a positive base, and loss-makers are the ordinary case here: measured, **TSLA is loss-making in 38 of 63 filed quarters, PTON 23 of 28, CRM 19 of 42**. So the two readings get their own dollar scales, stacked — the stock page's RSI/volume pane convention — and the note says they keep their own scales.

- **A ZERO LINE ONLY WHERE THE DATA SPANS ZERO**, which is the whole difference between a revenue panel and an earnings one: profitable or not is the reading, and a line with no zero on it cannot say which side it is on. The range is the **data's own**, padded in **pixels** rather than in value — padding in value put a zero line on a revenue chart, implying a crossing that cannot happen.
- **`valueChart` is a SIBLING of `lineChart`, not a flag on it.** That one rebases every series to a percentage, which is right for comparing two stocks and useless for a dollar figure; a function that draws "everything except" is harder to follow than two small ones — the reason `sparkSVG` sits beside `chartSVG`.
- **NO P/E LINE AT ALL, and that is a measurement.** The series spikes savagely where earnings pass through nothing — CRM's maximum is **8,014** against a median of 141.8, AMZN 1,287, F 443.7 — and is simply absent for every loss-making quarter. It appears as a then→now FIGURE instead, where `trailingPe` has already refused the multiples taken off a loss.

#### The refusals, each a measured case rather than an edge one
- **Under three trailing years is a REASON, not an empty chart.** Measured: **XOM has 0 usable trailing years** (the majors use a revenue tag `secfacts.js` does not map) and a fund files no statements at all.
- **No current share count means NO VALUE PANEL, never a fallback to the filed count** — that fallback *is* the forty-fold error. **Proved by reverting**: fails 4.
- **A multiple off a loss is a dash**, through the same `trailingPe` the adjusted pages use.

**The first live reading, which is also the coverage picture**: NVDA **68 trailing years back to 2009** with a **P/E median of 37.3** (the naive formulation gave 1.0), AAPL 70, MU 64 — and **JPM stops at 2014-09-30 with 23 points**, which is the filings-coverage gap this file already records for banks and REITs rather than anything this card does. **XOM and SPY draw no card at all**: the majors' revenue tag is unmapped and a fund files no statements. The label names the window it drew, so a 2014 end is visible rather than silent.

#### All four figures share ONE "then" — the window's own ends
They were taken from the first and last non-null value of each series, which is right for a line and wrong for a row labelled then→now: the loss-making fixture's P/E had no value at the start of its window, so `firstOf` **silently reported a later, profitable quarter** — `333.5× → 89.9×`, four figures with three different "then" dates and nothing on the card saying so. Found by the suite. An absent end is an em-dash now, which is what the note already promises.

#### THE TITLE STEP CLASSES WERE SCOPED TO `.sp-in` AND DID NOTHING HERE
`t2`/`t3`/`t4` are defined under the spotlight's container only. This card is `.evo-in`, so **they were inert**: the title stayed at 66px for every name, a 32-character name and a 45-character one both drew two 67px lines, and a 99-character one drew four and **269px** of a card that did not have it. Nothing threw. **The ninth instance of this project's class-scoping trap, in the other direction** — not a loose class capturing later markup, but a class scoped to one container and reused in another, where it is simply absent. The rules are shared now, and there is a check that a long name's title is **smaller** than a short one's.

- **The chart heights are MEASURED, not chosen**, across three artboards × eight name lengths: portrait **330/232**, square **194/136**, story **545/380**, leaving 50 / 31 / 34px at each board's own worst case. A single constant is a guess at variable content, and the square was **3px over** at its worst while the story left **306px unused** in a 1920px frame.
- **THE STORY'S WORST CASE IS A *SHORT* NAME**, the opposite of the other two boards: its base title is ~84px, so 23 characters is already two lines, where 99 characters drop to t4 and take one. A 14-character probe passed it — *"long" is a measurement, not an impression*, and here so is "short".
- **The window is NOT a layout dimension** — measured, the three windows draw to the pixel the same height — so the sweep walks NAME LENGTHS instead, with one check holding that down rather than assuming it.

#### Three faults a SCREENSHOT found and no assertion did
- **The market value figure was CLIPPED** (`$310.6B → $466...`) on the one figure the card is most about. Every artboard is 1080px wide, so a quarter of the figures row is the same **227px on all three** — and the figure value therefore **cannot take a per-artboard size**. The story's 30px override clipped all four; both overrides are deleted rather than retuned, since a rule that can only ever be wrong is residue that reads as intent.
- **The zero line carried no label** on a chart whose entire point is whether the company crossed it. The gridlines are evenly spaced *values*, so zero is almost never one of them; it gets its own, dropped where it would land on a gridline's.
- **The multiple was coloured green and red.** A P/E rising is good for a holder and bad for a buyer, so colour there is an implied verdict — the one thing this card must not make. Revenue, earnings and market value keep theirs: those are facts with a direction.

#### THE VALUE PANEL RUNS TO TODAY (2026-10-04, owner: "report upto today instead of last filed making the same assumptions you made on /adjusted")
**Reported as a discrepancy first: MSFT read `$2.77T` on this card and `$3.85T` on `/adjusted`, with P/Es of 20.7× and 28.8×.** Decomposed against production, neither was wrong — they were struck at **different dates**: 7.427B shares × **$373.02** (the close on 2026-06-30, MSFT's last filed quarter) against 7.445B × **$517.53** (the latest close). The cap gap is **+39.1%** and the price move over exactly that span is **+38.7%**; the 0.24% remainder is two slightly different filed share-count vintages. Same earnings both sides, so the multiple inherits all of it.

- **ONLY THE MARKET HALF COULD MOVE, and that asymmetry is the feature.** Prices exist for every session; there is no filing after the last filed quarter. So the value panel gains **one more point at the latest close** and revenue and earnings stop where the record does — carrying them forward would be inventing a figure. **The two panels now end on different dates**, which is honest and is itself the finding: the gap between the lines' right edges IS how stale the filings are.
- **THE LIVE P/E IS /adjusted's OWN ASSUMPTION**, stated as arithmetic: today's cap over the **last filed** trailing year. That is what a trailing P/E is everywhere in this app, and it is why the two pages now agree rather than differing by a quarter's price action.
- **BOUNDED AT 200 DAYS, because an unbounded extension draws a straight line across years of unfiled history.** Measured over 1,183 symbols: the newest statement filing is a median **61 days** old, p90 151, **98.4% inside 180**, then a thin tail of 19 reaching **5,661 days** — and **JPM's own trail stops in 2014**, so one segment would span twelve years of price action it never touched. 200 days on the period end is about two quarters, so the new segment is never more than twice the length of any other. **Proved by reverting**: the bound removed fails 2.
- **THE BOUNDARY PROBE FOUND A REAL BUG IN MY OWN CODE, which is what probing both sides is for.** The gap was computed from `Date.parse(d + 'T12:00:00')` — **local** time — so a span crossing the daylight-saving change gains an hour and a gap of exactly 200 days measured **200.04** and failed its own bound. It is `T00:00:00Z` on both ends now. **This is the one place local noon is wrong**: that rule exists for RENDERING a date (the card-dating lesson), and a *difference* must be taken in UTC. A one-sided check would have passed. **Proved by reverting**: fails 1.
- **THE FIGURES ROW NOW NAMES TWO DATES, and that is the half that answers the original question.** It carried none, so `MARKET VALUE $2.50T → $2.77T` read as *now* when it was end-of-June — the same cause as the owner's earlier question about why the chart ends on 30 June. The line reads *"Revenue and earnings to 2026-06-30 · market value and P/E at the 2026-09-30 close"*, or *"All four as of …, the last filed quarter"* where the filings are too stale to extend. **Proved by reverting**: dropping it fails 4.
  - **IT IS ONE FLEX CHILD WITH THE FIGURES, NOT TWO.** `.evo-wrap` is a `space-evenly` column, so a second child buys a **whole extra gap** on top of its own height — measured, the line alone cost **70px** on the square and overflowed the artboard. Wrapped in `.evo-foot` it costs its own ~30px.

#### THE FILL'S STRENGTH FOLLOWS THE BASELINE (2026-10-04, owner: "an area chart will be more impactful")
**The card already drew an area** — a vertical gradient from 0.26 to transparent — so the request is about its weight, and strengthening it is not a style change. **A filled area is read as a QUANTITY measured from the baseline; a bare line is read as a shape.** This project settled that once already on the short-interest strip, where the note records that *truncating a bar axis is the classic misleading chart* while a line *carries no such claim*. So a solid fill is only honest where zero genuinely sits on the axis, and the fill is solid exactly there: **0.42 → 0.05 where it does, the old 0.26 → 0 wash where it does not.**

- **THE OTHER WAY ROUND WAS MEASURED AND REFUSED.** Forcing zero onto every axis would let every card take the solid fill, at a cost taken over 99 real series (12 symbols × 3 windows): **62 are already zero-based and 11 cross zero**, so only 26 would move — and those are the mature companies the chart is least able to lose, with **PG's five-year revenue down to the top 10% of the panel**, AAPL's 19%, KO's and WMT's 22%. A flat strip at the top of a panel says nothing about the one company type whose revenue genuinely creeps.
- **THE READER IS NEVER LEFT GUESSING WHICH THEY HAVE, which is what makes two treatments safe rather than arbitrary.** The bottom gridline is LABELLED, so a solid fill always sits above a `$0` and a wash always sits above a real number. The fill's weight and the axis label say the same thing, and the check asserts exactly that correspondence rather than either alone.
- **ZERO IS ON THE AXIS WHEREVER THE RANGE REACHES IT, which is three cases and not one** — and the old `lo < 0 && hi > 0` test caught only the middle one. A series whose FLOOR the rule pulled to zero was closing `PADPX` (14px) below its own zero gridline; and **an all-negative series, whose CEILING the rule pulls to zero, was closing to the plot FLOOR** — so a company loss-making across the whole window had its mass drawn piling up from the bottom of the panel while zero sat at the top. **Upside down, and invisible at 0.26 alpha**, which is why strengthening the fill is what exposed it. It hangs from zero now.
- **THE BUSINESS PANEL CHARTS EARNINGS AND MARGIN AS WELL AS REVENUE, so both of those branches are live** — the revenue default can reach neither, and the first version of this check tested revenue alone. - Verified: **22 checks** over production's own series, plus the ground sweep (155 over 114 combinations) and the width sweep re-run unchanged. **Each case asserts the drawn fill against the drawn baseline**, so a treatment wired to the wrong test fails rather than passing on a sample that happens to agree — and the sample is deliberately mixed, **13 solid against 7 wash**.

### Flow — where the value sits, and how each sector has done (2026-10-05, owner's request)
**An eighteenth template, `flow`, fourth in the studio's picker: a one-step alluvial with the eleven sectors down the left sized by market value, three performance bands down the right, and a ribbon per sector flowing between.** The owner asked for *"composition (Market cap, Number of Stocks) of s&p by Industry and the performance of those industry"* with a Sankey attached as the reference, then narrowed it twice — *"I like the Sankey, Ignore the time, This is as of today always, Left side show the Composition of S&P by Industry, Right side show the YTD Performance"*, and then **"Just sector at the moment"**.

#### PERFORMANCE IS THE DESTINATION, NEVER THE WIDTH — the one decision the whole design rests on
The tempting version starts a ribbon at share of value and ends it at share of the GAIN, fanning wider or narrower. **It cannot be drawn, and the measurement is decisive**: at industry grain **50 of 112 industries have a NEGATIVE contribution this year**, the positives sum to **+17.0% against a basket of +13.7%**, and a ribbon has no negative width — so **3.3 points would have to be hidden**. Market cap flows (always positive) and the return only decides WHERE it lands, which makes the chart conserved by construction: every band is exactly the sum of the ribbons entering it.

- **TIME IS DROPPED, and the data could not have supplied it anyway.** The reference is a two-date Sankey; `fund_holdings` holds **two days**, so a composition-over-time chart has nothing to flow between. The owner dropped it independently.
- **SECTOR, NOT INDUSTRY, and the owner chose that after the measurement.** At industry grain the **top twelve are 63% of the index**, so the "Other" ribbon would be **37%** — the biggest element on the chart and the one that says least. Eleven sectors cover 100% with nothing pooled. (Industries per sector is median 10 / max 19, so a drill WOULD work; it is deferred, not refused.)

#### BEGINNING WEIGHTS, or the parts do not sum to the whole
Today's weight times the window's return is not the basket's return, and not by a rounding margin: measured on the index's own members, **the end-weighted parts overstate the basket by 24.6 points over the year and 15.7 points this year**, while the begin-weighted ones land on it EXACTLY at every horizon (gap 0.00 at a week, a month, YTD and a year), because a winner has already grown into the weight being applied to it. The start weight is reconstructed as `cap / (1 + r/100)` — which assumes an unchanged share count, the only approximation available since no share count is stored per date, and the note says so.
- **MY FIRST PROBE REPORTED THIS RECONCILING TO 0.0000pt AND WAS MEASURING ITSELF.** It computed the "whole" the same (ending-weight) way as the parts, so of course they agreed. **The claim a contribution makes is that the parts sum to the BASKET'S OWN RETURN** — `sum(cap_end)/sum(cap_begin) − 1` — and only the second probe, which computed that independently, showed the 24.6-point gap.
- **Proved by reverting**: end weights fail the suite outright, drawing +23.0% where the truth is +6.9%.

#### A BLANK SECTOR HAS TO LEAVE BEFORE THE INDEX IS STRUCK, not after
A stock whose profile has not been pulled yet belongs in no band — the rule `/pivot` and `/consolidated` both keep — but if it still counted toward the reference return the card would be measuring eleven sectors against a basket holding twelve things. **Measured: a gap of up to 0.10pt** (13.210 against 13.313 on the `out` cut), and **exactly 0.00000pt** once the index is struck over the sectored rows alone. The dropped rows are named in the note rather than disappearing; live, that is 1 of 504 inside the index and 3 of 738 outside.

#### THE BANDS ARE INDEX-RELATIVE, AND THE ORDER OF THE THREE TESTS IS WHAT KEEPS THE PALETTE HONEST
`r < 0 → down`, else `r > index → ahead`, else `behind`. **`r < 0` is asked FIRST**, so every sector in Ahead or Behind is non-negative **by construction** — which is what makes green always mark a sector that rose and red always one that fell, exactly the meanings those two colours carry on every other surface here. Ask "ahead" first instead and a year with a negative index paints a sector that lost money green. **Proved by reverting**: the other order fails 2, and the second names the harm — `drawn: #fb7185 #34d399` on a card where every sector fell.

- **FIXED BANDS COLLAPSE, measured over all five windows the picker offers.** Cuts at >30 / 15-30 / 0-15 / down put **TEN OF ELEVEN sectors in one band holding 98% of the value** on a single-day window — a chart that says nothing. The index-relative split never degenerates (3 bands today, 3 over a week, 2 over a month, 3 this year, 3 over a year) and needs no threshold that goes stale. **Proved by reverting.**
- The degenerate case is honest rather than broken: in a falling month every sector is Down, the card draws **one band at 100% of value**, and nothing is green.

#### THE RETURNS ARE OUR OWN AGGREGATE, NOT THE SECTOR FUNDS — deliberately unlike the Snapshot
`tplDay` reads the eleven Select Sector SPDRs and records why. **This card cannot**: its left column is the members' own market cap, so a right half taken from the fund would join two ends of one ribbon that describe different baskets. The gap is real and material — measured on YTD, **mean 2.84pt, and Communication Services reads +5.7% ours against −5.3% for XLC, a 10.9-point difference that puts it in a different BAND**; Technology is −6.3pt and Basic Materials −3.9pt.
- **Corroborated rather than asserted**: Energy reads **+41.0% ours against XLE's +41.9%**, a 1.0pt gap on the most extreme sector on the screen (refiners — MPC +168%, VLO +158%, PSX +109%). So the aggregate is right and the disagreements are basket composition, not arithmetic.
- The index funds and the eleven sector funds are removed from the pool first — a fund that IS a sector, inside that sector's own aggregate, double-counts it. **Proved by reverting** both ways.

#### A SMALL SECTOR STILL HAS TO BE VISIBLE
Basic Materials is **1.4% of the index**, which on the portrait's column is **seven pixels** — thinner than the label beside it and too thin for a ribbon to be followed. `FLOW_MIN` is 18px and the shortfall is taken back **from the slack above the floor in proportion**, so the distortion lands on the big nodes where it is a few percent rather than on the small ones where it would be everything. **The note says how many were floored**, the Size card's rule that a thing drawn at the floor says so.

#### EVERY DIMENSION IS MEASURED, NOT CHOSEN
- **The heights.** `.s-body`'s own `clientHeight` is **1128 / 858 / 1695** (portrait / square / story). That is NOT the day card's recorded 958 / 688 / ~1460 and neither is wrong — those are the room left BELOW its kicker and title, which on this card is 172px of the 1128. **The probe that first disagreed with both had divided `clientHeight` by the artboard's scale, and a CSS transform does not change layout pixels** — only `getBoundingClientRect` readings need converting, which is what made the body look 1600px tall and the slack impossible to reconcile. `FLOW_H` is 660 / 402 / 1120, leaving **32px of slack on all three** — the note takes `margin-top: auto`, so all the free space collects in ONE band between the drawing and the footnote instead of splitting at both ends, which is the fault the day card had to be rebuilt for.
- **The tracks.** `FLOW_TRACKS` is per artboard because the longest sector name is fixed and known: **"Communication Services" draws 197px at the label's own 17px**, so an ellipsis here is a width bug rather than the unavoidable thing it is on a company name. The binding width turned out to be the BAND SUB, not the name — **248px against a 220px box**, so it wrapped mid-phrase ("of the / value") on two artboards and the story's band name wrapped too. Dropping one article ("of value") took it to 213 and fixed all three.

- **A wrapped label is now a suite check**, and the honest line count is a **Range over the contents** — `getClientRects` on the element returns ONE border box however the text flows inside it, and these are blockified flex items. The documented trap, met again.

Inside `.s-title` a `.dim` span takes the display size, which is right for the Snapshot's one-word period and wrong for "and how each sector has done this year" — it **wrapped, so the heading took three lines and 202px** of a card whose whole content is a drawing.
